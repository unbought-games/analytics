# Architecture and trust boundaries

The composition root is `analytics-server`. `analytics-core` owns wire DTOs and the exact extension contract; ingestion and query/export modules own their domain operations, routers, tools and numbered migrations. `router(state, extensions, oidc)` merges extensions and rejects duplicate tool names. Foundation's standalone binary becomes the complete product when integration registers those modules; foundation health/auth tests alone do not establish A02–A13.

Axum provides HTTP routing, Tokio asynchronous execution, SQLx PostgreSQL access and migrations, serde/schemars wire schemas, and jsonwebtoken RSA JWT verification. Cargo.lock pins all builds: Axum 0.8.9, SQLx 0.8.6, jsonwebtoken 10.4.0, reqwest 0.12.28. SQLx 0.8 and jsonwebtoken 10 retain the established typed APIs used here; adopting newer major versions is separate compatibility work. Build was validated with Rust 1.99.0. MIT applies to repository source; dependencies retain their own licenses.

Primary documentation consulted: [Axum](https://docs.rs/axum/), [SQLx](https://docs.rs/sqlx/), [jsonwebtoken](https://docs.rs/jsonwebtoken/), [MCP released authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [OAuth JWT access-token profile](https://www.rfc-editor.org/rfc/rfc9068.html). MCP is pinned to **2025-11-25**, with stateless Streamable HTTP and JSON replies. Sessions/SSE are optional and not required here; GET/DELETE return 405. Remote clients authenticate each POST; MCP reconnect does not invalidate durable exports. Protocol/tool errors never contain provider secrets or SQL diagnostics.

All privileged operations use `Authorization::authorize`, including revalidation of held actors by queued jobs. Opaque credentials are 256-bit CSPRNG tokens; only SHA-256 verifiers are stored. Principals, token ceilings and any delegation parent's current grants intersect. An installation grant covers child resources, while a property/source grant cannot reach another resource. Dynamic changes apply to the next operation. Delegation depth is deliberately one and parent binding immutable. `grants()` reports intersections of action and resource independently.

PostgreSQL holds configuration, verifiers, authorization and audit records. Configuration uses validated typed JSON in `admin_objects`; schema versions are immutable and policy changes require increasing version. Source endpoints reject embedded credentials; source `secret_ref` is a restricted filename beneath deployment's secret directory. Configuration deletion removes configuration; deleting analytical history or artifacts belongs to the separately authorized ingestion/export lifecycle tools. Retention policies describe future collection; historical event policy versions remain evidence.

Admin mutations use one transaction plus an advisory transaction lock, with authorization checked after lock acquisition. Credential rotation revokes and issues in the same transaction. Every admin success is audited in that transaction; denied operations roll back then record a separate sanitized denial. Audit fields include principal, delegated identity, action, target, time and outcome; never request bodies, credentials or source secret values. Bootstrap and recovery use the same lock. Local recovery is a host operation, not a network endpoint.

External authentication uses an operator-configured OIDC/OAuth issuer. The resource server requires RS256 access tokens with explicit `at+jwt` type, matching issuer and resource audience, valid expiry/nbf, and a preexisting `(issuer, subject)` binding. ID tokens are rejected. Discovery/JWKS requests have timeouts and reject redirects; HTTPS is required except loopback fixtures. JWKS refreshes after five minutes or an unknown key after a ten-second refresh throttle. Each external token also receives a local verifier/revocation record so queued operations recheck expiry, revocation and live identity binding. No email-based association exists.

Public browser credentials remain ingestion-only and cannot authenticate the administration layer. Browser origin/proof/policy enforcement belongs to ingestion. MCP validates Origin against the configured public origin and supplies OAuth resource metadata in 401 challenges. All responses disable caching. No auth request or bearer value is logged.

Operational boundaries: migration access is separate from runtime access; deployments must use TLS, a protected secret volume, and database roles described in authentication/operations documentation. No production configuration, vendor account, package publication or deployment is part of this work.
