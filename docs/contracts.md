# Shared contract checkpoint v1

All wall times are RFC3339 UTC. UUIDs and logical time are strings. JSON object fields follow `analytics_core::dto`; unknown fields are rejected. `contracts/openapi.json` is generated reproducibly with `python3 scripts/generate-contract.py`; `--check` fails on drift. It merges foundation DTOs with the authoritative ingestion and query route generators, verifies every local reference, and retains browser wire compatibility. Individual Rust generators emit fragments for composition, not replacement of the published contract. Dependencies are pinned reproducibly by Cargo.lock. Compatibility changes require orchestrator coordination.

## Modules and composition

- `analytics-core` owns DTOs, `ApiError`, `ApiResult`, `AppState`, `Authorization`, `AuthContext`, `Resource`, `Grant`, `ToolDefinition`, `Extension`.
- `AppState { db: PgPool, auth: Arc<dyn Authorization>, config: Arc<ServiceConfig> }`. Configuration includes public base URL, export and secret directories, and maximum body bytes. Never accept source secret directories from clients.
- Each module implements `Extension`: `name() -> &'static str`, `router() -> axum::Router<AppState>`, `tools() -> Vec<ToolDefinition>`, `async call(&self, &AppState, &AuthContext, &str, serde_json::Value) -> ApiResult<Value>`. Foundation merges routers then supplies state; its MCP dispatcher routes tool names. Prefix tools `ingest_` / `query_` / `export_` to avoid collisions.
- Protected HTTP handlers extract `AuthContext`; every product operation calls `state.auth.authorize(actor, action, resource).await?`. Do not infer permission from authentication. MCP calls use the same domain operation. Public browser handlers validate property token/origin and current property policy; they never mint privileged AuthContext.
- Authorization rechecks principal, credential expiry/revocation, delegation and current grants on **every** operation. Queued jobs and artifact reads call it again. Store owner actor identity/credential ID, source/property scope and validate both. Installation `default` authority dominates child resources; `*` action is owner authority. Resource kinds: installation, property, source, export, principal. Resource IDs are strings. No missing-resource fallback to installation.
- Stable actions: `properties:read`, `properties:manage`, `policies:read`, `policies:manage`, `schemas:read`, `schemas:manage`, `sources:read`, `sources:manage`, `principals:read`, `principals:manage`, `grants:manage`, `credentials:manage`, `definitions:read`, `definitions:manage`, `status:read`, `audit:read`, `ingest:server`, `identity:manage`, `privacy:delete`, `query:read`, `exports:create`, `exports:read`, `exports:delete`. Query/download must also check underlying property/source. Public token is never valid as Bearer.

## Persistence and migration allocation

Foundation owns `0001_foundation.sql`; ingestion owns `0002_ingestion.sql`; queries owns `0003_exports.sql`. Integration may add later numbered migrations. Do not edit another task's migration.

Foundation tables: `principals`, `grants`, `credentials` (SHA-256 verifier of 256-bit random token only), `oidc_bindings`, `installation`, `audit_records`, `admin_objects`. Source secrets live outside database in protected deployment files; admin objects hold only a reference.

`admin_objects(kind text,id text,scope_kind text,scope_id text,value jsonb,revision bigint,updated_at timestamptz)` has primary key `(kind,id)`. Kinds: `properties` (`PropertyDefinition`, ID UUID, scope property/self), `policies` (`CollectionPolicy`, ID property UUID), `schemas` (`EventSchemaDefinition`, ID `<property UUID>:<name>:<version>`), `sources` (`SourceDefinition`, ID UUID, scope source/self), `definitions` (`SavedDefinition`, ID UUID, scope from query property/source). `load_object::<T>(&state.db, kind, id).await` retrieves typed values; caller authorizes separately. Property policy is canonical inside PropertyDefinition; policy administration updates that object atomically. Schema immutable versions must be retained by ingestion facts. Extensions must enforce enabled/policy configuration at collection and execution time.

## Wire and delivery semantics

Public browser ingestion uses `X-Property-Token`, server ingestion uses Bearer. `IngestBatch { events }`; per-item `EventAcknowledgement.status` is `accepted`, `duplicate`, `rejected`, or `conflict`, with code and optional decimal receipt cursor. Acknowledgement is sent only after commit. `clock`: `client`, `server`, `game`; game logical time remains separate. Browser event types cannot impersonate authoritative categories or set subject IDs. Retry same event ID and same payload. Campaign UTM values remain separate from experiment ID.

Collection profiles: `minimal`, `journey`, `identified`; default minimal, cross-property false. Schema property kinds: `string`, `boolean`, `integer`, `number`; allowlists exclude secret/field-content data. UTC windows are start inclusive/end exclusive. `HandoffResponse.handoff` is opaque, expiring and audience-bound. Redemption cannot accept an arbitrary identity assertion. `IdentityLinkRequest` requires trusted server authentication and evidence event. Browser `identify` can convey only trusted handoff/proof, never authoritative IDs.

`QueryRequest.kind` is module-defined (`analytics`, `postgres`, `prometheus_instant`, `prometheus_range`, `prometheus_discovery`, `sentry_issues`, `sentry_events`, `sentry_event`). It carries exactly one property/source scope. SQL/expression/vendor options live in `query`, values in `parameters`. `QueryBudget` is a requested maximum capped by operator policy. `ExportRequest.format` is `jsonl`. Status: `queued`, `running`, `complete`, `partial`, `failed`, `cancelled`, `expired`. `ExportManifest.format_version` is `1`; files use UTF-8 JSONL and SHA-256 lowercase hex. Large integers/decimals are strings described by column metadata. Every file has an authenticated URL, not just a local path. Source reads have independent timestamps; completeness, continuation and unavailable history remain explicit. Analysis consumes the exact manifest/dataset DTOs without a Rust dependency.

## Foundation administration

`POST /v1/admin/execute` and MCP `admin_execute` use the same `AdminRequest { operation, resource_kind, resource_id?, value? }`. Operations `list`, `get`, `put`, `delete`; principals, grants, credentials and OIDC bindings have typed handling. Credential issue/rotate/revoke are `issue`, `rotate`, `revoke` on kind `credentials`; issue value is `CredentialRequest`; rotate requires old credential ID. Raw token is returned once only by authorized issue/rotate. `GET /v1/me`, MCP `identity` inspect identity/capabilities; `GET /v1/admin/status`, MCP `status` inspect service state. No secret values in normal get/list/audit responses.

## Foundation implementation additions

Migration `0004_auth_sessions.sql` belongs to foundation; it adds external issuer/subject linkage to credential revocation records. It does not alter shared Rust DTOs.

Source creation and changes to `kind`, `endpoint` or `secret_ref` require installation-level `sources:manage`, even if the actor can manage that source. A resource-scoped manager cannot repoint a secret to an endpoint or substitute another source's secret. Other source metadata retains source-scoped administration.

Saved definitions use one authoritative lifecycle: `admin_objects(kind='definitions',id=UUID)` is the current active pointer; `admin_objects(kind='definition_versions',id='<UUID>:<version>')` is immutable version history with the same SavedDefinition DTO and scope columns. Both admin put and query_save must write history/current atomically; differing content at the same version conflicts. Reproduction first requires the active current pointer and its scope permission, then reads current or requested historical version. Deletion removes the current pointer; retained historical records cannot be reproduced while deleted. Scope is immutable even across deletion/recreation. Version strings are 1–120 characters and exclude colons. Query-specific metadata may supplement, never replace, this canonical lifecycle. Schema versions similarly retain `schema_versions` history to prevent version reuse after deleting active schema configuration.

Migration `0005_resource_generations.sql` gives every `admin_objects` INSERT/UPDATE a fresh globally monotonic `revision` using a database trigger and `admin_object_revision_seq`. Deleting/recreating the same UUID never reuses an earlier revision; updates that explicitly assign `revision+1` are also overridden by the trigger. Sequence gaps on rollback are expected. Queued queries and every artifact download compare captured source/property revision with the current row and deny absent or mismatched resources. Runtime roles need sequence USAGE. Never substitute a locally computed revision for the value read/returned by PostgreSQL.
